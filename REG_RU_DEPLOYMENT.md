# REG.RU — приёмка и публикация

Годовой хостинг Хост-А №124792581. Действующий домен, DNS и почта исключены из тестового размещения.

## Изолированный стенд

1. В ispmanager проверить технологический адрес и существующий корень сайта. Использовать его только после подтверждения, что он относится к №124792581. Не привязывать zakon-pravo24.ru. Закрыть стенд HTTP-аутентификацией и сохранить noindex и запрет обхода robots.txt.
2. Уточнить PHP и наличие PDO MySQL, fileinfo, mbstring, GD или Imagick. Записать фактическую версию MySQL и проверить utf8mb4. Использовать отдельную тестовую БД, отдельные учётные данные и синтетические записи. Конфигурация и резервные копии лежат вне веб-корня. Для фото установить лимит и проверять тип содержимого. Запретить исполнение скриптов в каталоге загрузок.
3. Проверить вход, выход, создание и редактирование контента, загрузку фото, сохранение после обновления, отсутствие доступа к приватным файлам и изоляцию админки. Скачать резервную копию и восстановить файлы и БД в отдельный контур.

## Релизы

1. Зафиксировать SHA принятого коммита. В релиз включить только HTML, assets, robots.txt и явно утверждённые файлы приложения. Проверить ссылки и сохранить SHA-256 архива. Не включать .git, базы, конфигурацию, ключи и пользовательские загрузки.
2. Сверить отпечаток SSH у Рег.ру. Пробный SFTP-вход выполнить с явным known_hosts и включённой строгой проверкой. Для автоматизации использовать отдельный ограниченный доступ к тестовому контуру. До подтверждения изоляции выполнять доставку вручную по SFTP с проверенной машины.
3. GitHub Actions на первом этапе только проверяет и собирает архив. Публикация после ручного утверждения выбранного SHA. Если хостинг поддерживает отдельный ограниченный ключ, хранить его в защищённом окружении GitHub, привязать workflow к staging и исключить автоматическую публикацию из PR.
4. Сохранить предыдущий архив, текущую конфигурацию, фото и отдельный дамп БД. Переключить релиз только после загрузки и проверки во временной директории. При откате вернуть файлы предыдущей версии, сохранив пользовательские данные. Изменения схемы требуют отдельного проверенного плана отката.

## Публичный выпуск

Сохранить запрет индексации до утверждения текстов, документов и SEO. Для допуска проверить полный список старых адресов, перенаправления 301, canonical, sitemap, robots, истинные 404 и мобильные страницы. Проверить контакты. В согласованное окно выпустить Let's Encrypt из ispmanager для корневого имени и www, проверить цепочку, перенаправления и плановое продление. Не менять NS и записи почты. Порядок подтверждения владения зависит от доступов к DNS и действующего маршрута сайта.

## Текущий кандидат

Требуются PHP 8.2+ с DOM и GD/WebP, Apache 2.4 с mod_rewrite и mod_authz_core. Редактор хранит данные в закрытом каталоге через атомарную замену файла с блокировкой. MySQL приложение пока не использует. В REG.RU отдельно проверить требования к тестовой базе, конфигурации PHP и хостинговым копиям.

Каталог задаётся переменной ZAKON_DATA. Создайте за веб-корнем приватный каталог с config.php, который возвращает массив с ключом password_hash. Значение создаётся через password_hash(..., PASSWORD_DEFAULT) локально, вне репозитория. Права на каталог и конфигурацию предоставляются только владельцу хостинга. Не публикуйте каталог private и архивы. Храните утверждённые шаблоны с изменяемыми полями стабильно, изменения шаблонов сверяйте на стенде с копией контента.

Кандидат по умолчанию закрывается Apache Require local. На отдельном тестовом виртуальном хосте замените эту директиву проверенной HTTP Basic аутентификацией с файлом паролей вне веб-корня. Сохраните 401 для страниц, статики и sitemap без входа. Релиз с нарушенной защитой не допускать к приёмке.

Локальная проверка: python tests/acceptance.py /path/to/php. Тест запускает PHP на loopback с одноразовым хранилищем. Проверка хостинговой конфигурации, адаптивности и восстановления остаётся отдельной.

## Восстановление доступа и данных

Владелец входит в Shell-клиент ispmanager через кабинет Рег.ру. Генерирует хеш нового пароля локально и передаёт только хеш на стандартный ввод ops/recover.php. Команда отзывает сеансы редактора и сбрасывает счётчик попыток. Скрипт запускается только из CLI. Пароли и хеши не хранить в GitHub. Копировать отдельно закрытый каталог состояния вместе с файлами media-*.webp и каталогами release-*. Для длительной эксплуатации требуется регламент очистки неиспользуемых файлов и старых снимков после подтверждённой резервной копии.

Маркер data-editor-fields в шаблоне является стабильным ключом. При перемещении блока сохранять атрибут и порядок прямых текстовых сегментов внутри блока. Перед удалением поля сопоставить его с новым шаблоном и проверить существующий черновик.
